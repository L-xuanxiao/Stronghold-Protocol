# 经验与预防措施

## 2026-10-04：封装既有开源项目前先查上游成果

- 问题：用户提出将现有游戏封装为离线 APK 时，尚未查询作者仓库的 PR、Issue、Releases 和相关 fork，就开始规划新实现并委派原生容器开发。
- 根因：只评估本地代码与构建环境，遗漏了现有解决方案检索，可能重复已经完成的工作。
- 预防措施：对既有开源项目的移植、打包、平台支持需求，先检索上游所有状态的 PR、Issue 及发布记录；若讨论提供 fork 或成品链接，核实版本、下载资源、维护者评审和适用条件，再决定直接使用、复用构建器或从头实现。
- 执行边界：需求确认只明确目标，不意味着跳过已有成果检索；在确定复用结论之前，只开展只读调查，不创建实现文件或委派实现。
